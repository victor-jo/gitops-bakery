# gitops-bakery `--with-ml` — the hand-built ML lab as an install option

**Goal:** `install --with-ml` rebuilds the hand-built ML lab on any bakery lab: MLflow, JupyterLab, Feast and Kubeflow Pipelines 2.18, each reachable by name through cloud-provider-kind. The exercise code is kept in `labs/ml/`.

## Decisions (with the user)

- **Opt-in.** The flag is stored in `state.options.ml` and a plain rerun keeps it. Without the flag the install steps are exactly the v0.1.1 ones.
- **cloud-provider-kind.** The user runs `sudo cloud-provider-kind`, and the installer only checks for it. Host names are built from the gateway IP each namespace actually gets, so nothing from the hand-built lab's IPs is hard-coded.
- **Scope.** The installer covers the platform and the seed data. Training, choosing `champion` and running the pipeline stay exercises.
- **No upstream example code in the repo.** The example repositories carry no license. Data, notebook and step code are fetched at a pinned commit, and only this lab's edits are stored, as `patch_notebook.py` and `labs/ml/kfp/upstream/lab.patch`. Feast definitions, pipeline code and scripts are this lab's own.
